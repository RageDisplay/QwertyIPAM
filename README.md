# VectrixIPAM

Простой IPAM (IP Address Management) на Go: реестр подсетей и адресов с
веб-интерфейсом и кнопкой автоматического обнаружения хостов в подсети.

## Возможности

- Учёт подсетей (CIDR, описание, VLAN).
- Учёт адресов внутри подсети (hostname, MAC, статус, владелец, заметки).
- Обнаружение "живых" хостов в подсети (ICMP ping с несколькими попытками, с
  fallback на TCP-connect, если ICMP недоступен) и автодобавление найденных
  адресов в реестр.
- Автоматическое определение hostname (reverse DNS) и MAC-адреса (сырые ARP-
  запросы прямо из процесса, без обращения к ОС хоста — см. ниже про L2).
- Открытая подсеть запоминается в браузере и восстанавливается при
  перезагрузке страницы.
- Один бинарник, БД — SQLite-файл, без внешних зависимостей.

## Запуск через Docker

```bash
docker compose up -d --build
```

Приложение будет доступно на [http://localhost:8080](http://localhost:8080).
Данные хранятся в docker-volume `vectrixipam-data`.

### Про ICMP-обнаружение в Docker

Для unprivileged ICMP ping контейнеру нужен `CAP_NET_RAW` (уже добавлен в
`docker-compose.yml`) и открытый `ping_group_range` на хосте (тоже задан через
`sysctls`). Если по какой-то причине ICMP всё равно недоступен (например,
некоторые managed-окружения запрещают `cap_add`), сканер автоматически
переключается на проверку через TCP-connect по портам 80/443/22/3389/445 —
работать он продолжит, просто чуть менее точно определяет "живые" хосты без
открытых портов.

Каждый хост опрашивается несколько раз подряд (в рамках одного запроса
"Обнаружить адреса"), чтобы не терять ответы из-за единичной потери пакета —
одного нажатия кнопки должно хватать, чтобы найти всех отвечающих хостов.

### Про определение MAC-адреса

MAC определяется сырыми ARP-запросами, которые процесс отправляет сам
(`github.com/mdlayher/arp`), не полагаясь на ARP-таблицу или команды ОС хоста
— работает одинаково независимо от того, где и на чём запущен контейнер.

Ограничение здесь сетевое, а не программное: **ARP работает только в
пределах одного L2-сегмента**. Обычная Docker bridge-сеть (как в
`docker-compose.yml` по умолчанию) помещает контейнер за NAT в отдельный
виртуальный L2-сегмент, поэтому реальные MAC-адреса устройств в вашей
физической сети оттуда не видны — в этом случае discovery по-прежнему найдёт
хосты и их hostname, но поле MAC останется пустым.

Чтобы получить MAC-адреса, нужно дать контейнеру прямой доступ к вашей LAN,
например:

- `network_mode: host` (просто, но только Linux, и тогда контейнер слушает
  порт 8080 прямо на хосте — уберите проброс `ports`);
- или macvlan-сеть, подключённая к физическому интерфейсу хоста.

Также нужен `CAP_NET_ADMIN` (уже добавлен в `docker-compose.yml`) для
открытия raw-сокета ARP.

## Запуск локально (без Docker)

Требуется Go 1.23+.

```bash
go run .
```

По умолчанию слушает `:8080`, БД пишет в `/data/vectrixipam.db` — для
локального запуска переопределите путь:

```bash
VECTRIXIPAM_DB_PATH=./vectrixipam.db go run .
```

## Переменные окружения

| Переменная                 | По умолчанию              | Описание                          |
|-----------------------------|----------------------------|------------------------------------|
| `VECTRIXIPAM_DB_PATH`       | `/data/vectrixipam.db`     | Путь к файлу SQLite                |
| `VECTRIXIPAM_LISTEN_ADDR`   | `:8080`                    | Адрес, на котором слушает сервер   |

## API

- `GET/POST /api/subnets`, `DELETE /api/subnets/{id}`
- `GET/POST /api/subnets/{id}/addresses`
- `PUT/DELETE /api/addresses/{id}`
- `POST /api/subnets/{id}/discover` — запускает сканирование подсети и
  сохраняет найденные адреса в БД.

## Заметки

- Веб-интерфейс не имеет авторизации — предполагается использование во
  внутренней доверенной сети. При необходимости легко добавить basic-auth
  через middleware в `main.go`.
- Поддерживаются только IPv4-подсети размером до `/16`.
